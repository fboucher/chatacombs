# Chatacombs

Chat-driven dungeon crawler that runs in a streamer's Twitch chat. A standalone Node service; chat bots (e.g. CloudBot/CeeBee) are HTTP/SSE clients of it, not owners of game logic.

## Current state: pre-code

No `package.json` or `src/` yet. Only docs and tooling are committed. Phase 1 (engine) is being built issue-by-issue — do not invent scope. The authoritative current plan is the open issues, parented under [Epic #1](https://github.com/fboucher/chatacombs/issues/1), with slices #9–#15 describing each engine slice. Work through those issue bodies; treat the epic body as the deliverable contract.

## Sources of truth (read before writing code)

- `chat-dungeon-crawler-design.md` — game rules, command vocabulary, room types, game events, party/economy/pacing behavior. The glossary.
- `PLAN.md` — architecture, DB schema, HTTP/SSE API spec, roadmap. Tech stack is fixed there: **Node 22+, native ES modules (`"type": "module"`), Express, `better-sqlite3`, `node --test`**.
- Open issues — the actual slice scope (issues #9–#15 under epic #1).

There is no code yet to verify against; the docs describe the target state.

## Hard rules

- **Code owns the truth, AI narrates.** Deterministic engine code controls rooms, monsters, HP, loot, votes, dice, XP. The AI only adds flavour inside that context and must never alter facts. AI failure always falls back to procedural templates — the game keeps running.
- **Engine phase (Phase 1) is offline.** No network, AI, or database calls. Randomness must be seedable/deterministic so tests pass without services.
- **Verify with `node --test`** (built-in runner — no jest/vitest). `npm test` is defined by slice #9 and runs the `node --test` suite in `test/`.

## Vocabulary to match (design doc, not invented here)

- Commands: `!vote`, `!theme <idea>`, `!explore`, `!go <exit>`, `!attack`, `!defend`, `!item <name>`, `!heal @name`, `!hero`. Avoid words CloudBot already owns (`!search`, `!use`, `!bag`, `!dice`, `!roll`, `!stats`, `!rpg`, `!start`, `!stop`). Unknown commands are ignored — bots forward all chat safely.
- Room types: `entrance`, `empty`, `trap`, `treasure`, `monster`, `boss` (boss is the final room).
- Game events: `adventure_started`, `room_entered`, `dice_roll`, `player_healed`, `rare_loot`, `boss_appears`, `monster_defeated`, `player_knocked_out`, `party_wiped`, `dungeon_cleared`.
